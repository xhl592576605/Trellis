## 已复现的缺陷

### F1 / P1：外部存储项目名未在写入端校验

位置：packages/cli/src/utils/external-store.ts:82、107。

prepareExternalStorage(storage, '../escaped', codeRoot) 成功写入 storage 的兄弟目录 escaped/project.json。CLI 的 options.project 直接传入该函数。Python 的项目名检查不能保护先发生的 TS 初始化写入。项目目录 symlink 也未做 storageRoot realpath containment：Python load_store 接受 storage/linked → storage 外目录，且绑定文件缺失时仍返回成功。

影响：AC2/AC9/AC13、R8；项目根边界不成立。需要在公共写入/解析 chokepoint 验证单目录名、保留名和真实目录归属。

### F2 / P1：绑定校验与显式配置错误策略不一致

位置：external-store.ts:35、114；common/external_store.py:122、load_store；opencode/lib/trellis-context.js:44；Pi/OMP workflowDir；shared-hooks/session-start.py:309。

复现：无 Git 的 A 先创建 project=plain，B 再以相同 project 初始化，成功覆盖 project.json 的 codeRoot。Python 在没有 gitCommonDir 的绑定上提前返回，允许无关代码目录访问；TS/OpenCode workflow resolver 完全不检查反向绑定。显式损坏 JSON 时 TS resolveWorkflowDir 静默返回 codeRoot/.trellis；多个 hook/extension 也有同类回退。

影响：AC2/AC13/AC9；违背“明确配置损坏不得回退”和“只有已验证当前绑定目录可授权”。

### F3 / P1：真实 init 后首次 journal 不能完成

位置：configurators/workflow.ts:193；scripts/add_session.py:1227；common/developer.py:ensure_workspace。

真实 CLI init --storage <store> --project cli-project --claude -y 返回 0；随后直接执行外部 scripts/add_session.py --title after-init --no-commit，返回 1。日志已写入，但更新 index.md 报错：

```text
Error: Markers not found in index.md. Please ensure markers exist.
[BLOCKED] Checkpoint: session 1 is in journal-1.md but index.md was not updated.
```

init 写入的是 agentProgressIndexContent 总览索引，不含 add_session 要求的 auto 标记；ensure_workspace 只在 workspace 目录不存在时调用，已有 index 不会被修复。现有 Python journal 测试从不存在 workspace 的 fixture 开始，绕过了该问题。

影响：AC5/AC14/AC15；外部 init→journal 的基本闭环失败。

### F4 / P1：无浏览链接时 Python 核心读取仍使用代码根拼接

位置：common/workflow_phase.py:28；common/task_context.py:92、_resolve_context_entry_path；common/session_context.py:625、768、867；add_session.py:1532。

从真实外部路径调用 get_context.py --mode phase 返回 1，FileNotFoundError 指向 codeRoot/.trellis/workflow.md；task.py add-context <task> implement .trellis/spec/guides/index.md 返回 Path not found。启动 task 后 get_context.py --mode record --json 的 currentTask 为 null，因为 load_task(repo_root / current_task) 仍查找不存在的词法路径。add_session 的活动任务 package 推断存在相同拼接遗漏。

影响：阶段 1/2/3、AC3/AC15；需要覆盖 phase、task materials、record context，而非只验证 task current 输出。

### F5 / P1：Agent 生成命令和提示未注入外部真实路径

位置：templates/common/commands/start.md、continue.md:10、finish-work.md；shared-hooks/session-start.py:470、760、832、932。

生成模板继续执行 python3 ./.trellis/scripts/get_context.py。删除浏览链接后该命令返回 2（can't open file）；shared SessionStart 输出包含旧脚本路径，不包含外部 get_context.py 的真实路径。Hook 自身能看到活动任务，不能证明模型后续可运行 continue/phase/finish-work。

影响：阶段 3 的核心评审门、AC3/AC15。

### F6 / P1：共享 workspace 并发写入可静默丢失日志

位置：scripts/add_session.py:1322、1376；common/developer.py:ensure_workspace。

使用两个进程同时调用 add_session(title, auto_commit=False)，仅在 journal 写入前加入测试屏障，确保两者都已完成读取。两个进程均返回 0，但最终 journal-1.md 只保留 parallel-A 或 parallel-B 中的一条。atomic replace 保证单次文件替换，不保证读改写事务互斥；日志编号、journal 和 index 更新缺少项目级临界区。

此外 active_task.py:267 将所有 checkout 写入同一 .runtime/sessions/<contextKey>.json。相同 TRELLIS_CONTEXT_ID 跨两个 checkout 启动不同任务时，后者覆盖前者；当前没有设计要求的 checkoutKey 隔离。该结论限定于相同 session key 场景，不声称不同 key 必然冲突。

影响：阶段 2、R4、AC5/AC7；串行/checkout 分域不是仅阶段 5 提交实现的事项。

### F7 / P1：安装 manifest 共用，首次外部模板 hash 也缺失

位置：utils/template-hash.ts:55、397；commands/init.ts:2046、2076。

在同一 Git 仓库的 main/worktree 上分别真实执行 init --storage <store> --project shared --pi -y 和 --codex -y，两个命令均返回 0。第二次 init 后，从第一个 checkout 读取的 hash 中 .pi/ 条目由 5 变为 0，出现 4 个 .codex/ 条目。公共 hash 与每 checkout 接入 hash 未分域，AC12 未实现。

首次无链接 init 后，manifest 中 .trellis/ 条目数为 0：collectFiles 已能遍历外部目录，但 initializeHashes 随后仍通过 path.join(cwd, relativePath) 读取文件；浏览链接此时尚未创建，所有外部公共模板读取失败被忽略。该缺陷会破坏后续修改检测和更新保护。

影响：阶段 4、AC12、R7；即使单 checkout 也缺失公共模板安装基线。

### F8 / P1：默认 init 与重复 init 未统一到配置模式

位置：commands/init.ts:1156、1162、1191、1263。

普通 init --claude -y 返回 0，但不生成 .treills.conf.json，仍创建实体 .trellis；只有显式 --storage 才进入新模式。对已有有效定位配置的项目删除浏览链接后执行 init --claude -y，也创建实体代码根 .trellis，产生两份 workflow 数据。运行模式仍由本次参数和浏览入口存在决定，未按现有根配置收敛。

影响：阶段 4、D1/D4、AC1/AC14。

### F9 / P2：update 与浏览链接管理仍不完整

位置：commands/update.ts:2108；createBrowseLink 及 init 接入管理。

配置有效、外部数据完整、删除浏览链接时，update --force 输出 Trellis not initialized 并以 0 退出。未在此场景中执行网络版本检查，因为已被入口 guard 拦截。

使用 core.excludesFile=/dev/null 隔离本机全局忽略配置后，新建浏览链接未被 git check-ignore 识别；没有 init 写入的本机 Git 排除规则。新存储根无 .gitignore，但项目内 .gitignore 已忽略 .runtime 等目录，不能将其描述为运行态完全未忽略。根配置/链接的 manifest-prune 和生命周期归属仍待完成。

影响：阶段 4 的版本/平台识别和链接管理；后续阶段 6/7 也依赖这些边界。
