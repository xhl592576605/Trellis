本轮按 trellis-check 核对 PRD R5–R8、design §6–10、实现、清单和真实 Git 行为；GitNexus 按用户既有指令跳过，未派发子代理。发现的问题已直接修复，增加 23 个测试：全量由 1718 增至 1741。没有提交/推送代码，没有迁移本仓库自身数据。

## 阶段 5：外部任务级提交

- **P1 — required commit 归属绕过**：session_auto_commit=false 曾绕过 foreign-marker 检查；未带标记的手工日志/索引编辑也会被整文件夹带。现在无论中间开关如何，最终提交都检查共享文件的干净基线、写后快照和 foreign markers，冲突保留内容并返回非零。
- **P1 — 未提交却返回成功**：Git ignore 导致的 COMMIT_BLOCKED 曾被 --require-commit 当作成功；已提交的幂等键早退也跳过新增 include 文件。现在 required 模式严格检查退出结果，已提交键仍处理显式文件和归档恢复。
- **P1 — 延迟归档身份丢失/跨会话夹带**：--no-commit 没有保存恢复身份，原恢复循环又会处理同项目所有会话。现在每次归档保存精确目标、受影响子任务和 checkout/session owner，状态更新持有 storage 锁；默认只恢复自己的记录。接手早先会话须显式指定 --require-commit --recover-archive <task>。损坏状态明确失败。
- **P1 — 失败重试漏掉源删除**：git rm --cached 已成功、commit 被 hook 拒绝后，重试只用 ls-files 判断源是否受跟踪，导致提交只含归档目标。现在同时检查 HEAD，测试直接断言恢复后 tasks 下没有残余源删除。
- **P1 — 归档范围过宽**：不同月份存在同名任务时曾收集多个目标；子任务 task.json 已有其他修改时也会整文件带入。现在使用持久化的精确年月目标，相关子任务元数据脏时在修改前停止。
- **P2 — include 边界**：目录曾可作为 include，且缺失的已跟踪文件无法纳入删除。现在只接受明确产品文件/已跟踪删除，拒绝目录和 runtime/cache，Git staging/commit 使用 literal pathspec。

主要代码：.trellis/scripts/add_session.py、common/data_git.py、common/safe_commit.py、common/task_store.py；发行模板双树已同步。finish-work 公共模板、Copilot 模板和 dogfood skill 同步跨会话恢复说明。

## 阶段 6：显式迁移

- **P1 — gate 被空操作清单绕过**：存储门禁原位于 hasMigrations 分支。现在独立于 rename/delete 数量，位于 hash pruning/模板变更前；通过模拟 0.7.0 的真实 update 流程验证无写入硬失败。顺带修正普通 dry-run 的 manifest pruning 与无文件变化时版本写入。
- **P1 — untracked import 漏提交/失败假成功**：原先先 diff HEAD，存储已有 HEAD 时新项目文件不可见；提交失败只警告，且命令临时覆盖作者。现在先 staging，使用用户身份和 hooks，失败阻止切换并保留检查点；精确提交路径保留其他 staged 数据。新建的根 ignore/attributes 仅纳入初始化范围。
- **P1 — 复制和 workspace 重试不安全**：旧实现 force-copy 到目标、原地转换，多次重跑会冲突或覆盖后续写入；常见的 workspace/index.md 与作者 index.md 也冲突。现在先构造/校验独立导入快照，在快照中转换；目录索引移到 history/index.md，其他作者入 history；发布前比对目标，只允许缺失或相同字节。
- **P1 — 中断状态无法续走**：原先写根配置后早退只修链接，实体旧目录仍占位；重跑也没有任何检查点。现在有 prepared/committed/switched/refreshed/complete 状态、源/快照摘要和确定的备份名，覆盖原目录已改名但配置未发布、配置已发布但状态未更新、接入刷新已执行但检查点未落盘等故障。
- **P1 — 迁移后仍依赖手动第二次 update**：旧命令仅拷贝旧脚本/接入，提示用户再 update。现在同一事务调用现有 hash-gated update，默认保留修改；最终提交只包含本次模板/迁移输出，重试期间出现的 sibling task 保持未提交。
- **P2 — dry-run 和链接边界**：已迁移项目 dry-run 曾修复链接；copy/verify 对源链接、嵌套缓存处理不一致。现在 dry-run 无链接修复，源 symlink/特殊对象在创建 storage 前拒绝，过滤与校验规则一致。
- **并发**：Node 迁移通过 Python 子进程持有和脚本相同的 workspace→storage OS 锁，避免一套新锁协议与真实 journal/archive writer 互不排斥。EOF/父进程退出释放锁。

主要代码：commands/storage-migration.ts、utils/storage-migration-lock.ts、commands/update.ts、0.7.0 manifest。迁移指南与新恢复/刷新流程同步。保留的用户模板若仍不兼容，仍需按 update 的冲突输出人工合并。

## 阶段 7：uninstall / ablate / restore

- **P1 — 物理 browse 入口被递归移除/备份**：配置有效而 .trellis 被换成实体目录时，原实现会操作其中用户数据。现在 uninstall/ablate 在任何变更前拒绝这种占位；只有链接可移除。
- **P1 — 无浏览链接时 ablate 误判未安装**：现在以配置模式判断安装，缺失链接仍能 ablate/restore；还原保持原先无链接状态。
- **P1 — restore 接受已改绑目标**：原实现只验证 project.json 存在。现在复用 readExternalStore(codeRoot, backupConf)，执行相同路径、包含关系及 Git common-dir 身份校验；目标缺失/改绑时零 checkout 写入。
- **P2 — uninstall 计划阶段修改共享 manifest**：原 prune 可写外部 shared hashes；现在在内存中处理，显式根配置删除去重。外部产品数据不进入生命周期事务。

主要代码：commands/ablate.ts、commands/uninstall.ts、shared-hooks/external-store.js 及声明；managed-removal 原链接 unlink 语义保留。
